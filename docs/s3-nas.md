# S3-хранилище на своём NAS

Как поднять на NAS S3-совместимый сервер, чтобы moth-amp хранил там вашу музыку,
кэш и настройки и они были общими для компьютера и телефона.

Используется [RustFS](https://github.com/rustfs/rustfs) — S3-совместимый сервер под
лицензией Apache 2.0, работает в Docker. (MinIO больше не публикует бесплатные
образы, поэтому он здесь не рассматривается.)

```
 ПК с moth-amp ─┐
                ├──►  NAS : 9000  (RustFS)  ──►  папка data/ на дисках NAS
 телефон ───────┘        бакет music/moth-amp/…
```

## Что нужно

- NAS с Docker: Synology (DSM 7.2+, «Container Manager»), QNAP («Container Station»),
  TrueNAS SCALE, Unraid или любой Linux-сервер.
- Постоянный IP NAS в домашней сети: закрепите его в настройках DHCP роутера.
- Точное время на NAS (NTP включён). Запросы к S3 подписываются, и при расхождении
  часов больше 15 минут сервер их отклоняет.

## 1. Папка и файлы

Готовые файлы лежат в репозитории в `deploy/nas/`. Создайте на NAS папку,
например `/volume1/docker/moth-s3` (Synology) или `/share/Container/moth-s3` (QNAP),
и положите туда `docker-compose.yml` и `.env.example`.

По SSH:

```sh
cd /volume1/docker/moth-s3
mkdir -p data logs
# RustFS работает от пользователя с UID 10001 — ему нужна запись в эти папки.
sudo chown -R 10001:10001 data logs
```

## 2. Ключи

```sh
cp .env.example .env
openssl rand -base64 30     # получившуюся строку — в MOTH_S3_SECRET_KEY
nano .env
```

`MOTH_S3_ACCESS_KEY` — любое имя латиницей, `MOTH_S3_SECRET_KEY` — длинная
случайная строка. Эти же два ключа потом вводятся в moth-amp.

## 3. Запуск

**По SSH (любой NAS или Linux):**

```sh
docker compose up -d
docker compose logs -f      # Ctrl+C — выйти из логов
```

**Synology без SSH:** Container Manager → «Проект» → «Создать» → путь — папка из
шага 1, источник — существующий `docker-compose.yml` → «Далее» → «Готово».
Права на `data` и `logs` всё равно нужно выдать (шаг 1): без них контейнер не сможет
писать. Если SSH выключен, включите его на время в «Панель управления → Терминал».

**QNAP:** Container Station → «Приложения» → «Создать» → вставить содержимое
`docker-compose.yml`, а значения ключей вписать прямо вместо `${…}`.

**TrueNAS SCALE / Unraid:** «Custom App» / «Add Container» с теми же параметрами:
образ `rustfs/rustfs`, порт `9000`, переменные `RUSTFS_ACCESS_KEY` и
`RUSTFS_SECRET_KEY`, папки `/data` и `/logs`.

## 4. Проверка

С компьютера в той же сети:

```sh
curl -i http://<IP NAS>:9000/
```

Ответ `403` — **это хорошо**: сервер работает и требует подпись. `Connection refused`
или тишина — см. «Неполадки».

## 5. Подключение в moth-amp

Вкладка «моя музыка» → «Подключить S3»:

| Поле | Значение |
|---|---|
| Адрес (endpoint) | `http://<IP NAS>:9000` |
| Регион | `us-east-1` (для своего сервера подходит любой) |
| Бакет | `music` — **создастся сам** при первом подключении |
| Ключ доступа | `MOTH_S3_ACCESS_KEY` из `.env` |
| Секретный ключ | `MOTH_S3_SECRET_KEY` из `.env` |
| Адреса в стиле path | **включено** |

Те же данные — на телефоне. После подключения moth-amp сам перенесёт в бакет кэш и
настройки эквалайзера, а «Загрузить mp3/flac» положит туда ваши файлы.

## Вне дома

**Не открывайте порт 9000 в интернет.** Надёжнее всего — VPN до домашней сети
(WireGuard на роутере, Tailscale и т.п.): с ним телефон обращается к NAS по тому же
адресу `http://<IP NAS>:9000`, как дома.

Если всё же нужен публичный адрес — только через HTTPS, например обратным прокси
Caddy на NAS или роутере:

```
s3.example.com {
    reverse_proxy 127.0.0.1:9000
}
```

и в moth-amp адрес `https://s3.example.com`. Прокси должен передавать заголовок
`Host` без изменений (Caddy делает так по умолчанию), иначе подписи не сойдутся.

## Что лежит в бакете

```
music/
└─ moth-amp/
   ├─ tracks/        ваши mp3/flac — «Исполнитель — Название (id).mp3»
   ├─ covers/        обложки из тегов
   ├─ library.json   список вашей библиотеки
   ├─ cache/
   │  ├─ yandex/     кэш треков Яндекса (по правилам подписки)
   │  └─ index.json
   └─ settings/      настройки, например equalizer.json
```

На диске NAS это папка `data/`. Ваша музыка — обычные файлы с тегами.

## Резервные копии

Бэкапьте папку `data/` средствами NAS: снапшоты Btrfs/ZFS, Hyper Backup (Synology),
HBS (QNAP). Перед копированием можно остановить контейнер (`docker compose stop`),
чтобы индексы были в согласованном состоянии.

## Обновление

```sh
docker compose pull
docker compose up -d
```

Данные в `data/` при обновлении не трогаются.

## Неполадки

| Что видно | Причина и решение |
|---|---|
| `SignatureDoesNotMatch`, `RequestTimeTooSkewed` | Расходится время на NAS и устройстве — включите NTP. Проверьте, что «Адреса в стиле path» включены. |
| `AccessDenied`, `InvalidAccessKeyId` | Неверные ключи: сверьте с `.env`. После правки `.env` — `docker compose up -d`. |
| `Connection refused`, долгое ожидание | Контейнер не запущен (`docker compose ps`), порт закрыт файрволом NAS, или телефон не в домашней сети и без VPN. |
| В логах `permission denied` | Не выданы права: `sudo chown -R 10001:10001 data logs`. |
| Через прокси `SignatureDoesNotMatch` | Прокси меняет `Host` или путь: проксируйте весь домен на `:9000` без префиксов. |
